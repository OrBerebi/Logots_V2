2. --no-catalog reliability testing: 4 successes, 1 failure, cause found
----------------------------------------------------------------------------
Ran --no-catalog (species identification without the reference catalog)
five times total, all against the same snake plant, across different scan
conditions:

  1. Catalog ON (baseline), static             -> success, high conf, 10.2s
  2. Catalog OFF, static                        -> success, high conf, 9.4s
  3. Catalog OFF, static (repeat) + one
     hand-driven live run                       -> success x2
  4. Catalog OFF, ~112s recorded DYNAMIC scan
     (continuous rotation), SIM replay          -> FAILED, 0 plants, 5.2s
  5. Catalog OFF, ~67s recorded LOW-MOVEMENT
     scan (camera pan/tilt only, body still),
     SIM replay                                 -> success, high conf, 11.1s

Root cause of the one failure (#4), found by code inspection, not
guessing: initiation.py only ever sends SURVEY_FRAMES=8 evenly-time-sampled
frames out of the whole survey to the vision model (np.linspace over
however many 1fps frames collect_pass() gathered), with zero
content-awareness — no check that a sampled frame contains the plant, no
motion-blur filtering. During continuous rotation, all 8 samples can easily
land on frames where the plant is at the frame edge or out of view. This is
NOT a SIM-only artifact — the same code path and 8-frame limit applies to
live real-robot operation too, so it's a real weakness in how the robot
would do an actual room survey, not just a testing quirk.

3. The Asaph Mac-vs-Jetson discrepancy — reasoning corrected mid-day
--------------------------------------------------------------------------
Background: Asaph reported his own Mac "macbook fix" (an attempt to run the
identical E2B model via llama.cpp on his Mac) failing the --no-catalog
task, while a bigger model (E4B, via the existing GemmaBrain/transformers
path, no fix needed) succeeded on his Mac.

First pass at explaining this leaned on "model size" (E2B borderline, E4B
more capable) — but that's the wrong comparison: it doesn't explain why the
SAME E2B model succeeds reliably on the Jetson but failed on his Mac.
Corrected framing: the real open question is same-model-different-platform,
and the live candidates are (a) CUDA vs Metal backend non-determinism on a
borderline decision, (b) an actual difference/bug in how his "macbook fix"
reproduces the setup (build flags, GPU offload not engaging, mmproj
mismatch, etc.), or (c) a different, harder test plant than ours.

Point (c) is now ruled out for a controlled retest: after finding and
understanding the 8-frame issue (section 2), we have a clean recording
(#5 above) that succeeds confidently and unambiguously here — a good
candidate to send Asaph for an apples-to-apples test. If his Mac fails on
this exact recording, that's now a meaningful signal pointing at his
implementation rather than the model or scan conditions. Plan: send him
recordings/session_20260913_104159/session_20260913_104159.csv with a
message asking him to run --no-catalog against it in SIM mode and report
back.

  controls, LOOP checkbox, keyboard hint) into a left-hand sidebar column.
  The four main panels (DRIVE&CAM, IMU, AUDIO, VIDEO) keep their original
  2x2 grid arrangement and height, unchanged.

  within the current pass, resetting to 0% on each loop wrap.

  Pitch label. Cause: unnecessary manual space-padding in the label text

  stacked, so the alignment served no purpose) plus a fixed 6-character
  numeric field, pushing the combined row width past the panel's boundary.
  Fixed by dropping the manual padding, tightening internal label padding,
  and simplifying the numeric format.
